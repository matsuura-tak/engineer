### 7.2 「ひとこと解説」（insight）の書き方の決まり
形（スキーマと AC-38 で機械が検査する）：
- 前後の空白を除いて 1〜120 字。字数はコードポイント（JS の `[...str].length`）で数える。
- 改行とバッククォート（`）を含めない。画面では `<p>` 1 つに textContent でそのまま入る（contracts/strings.md の 5）ので、行内コードは書けない。コマンドや識別子は装飾なしの英字で書く（例：POST、memo、force push）。
- 文言の語の検査（AC-35）の対象ではないが、「連続」「途切れ」「逃した」は使わない（完了直後の画面に並ぶため）。

中身（pdm が守った決まり。Takuma の確認の観点でもある）：
- 完了した直後にだけ見える「発見」の一言にする。課題の本題を 1 段上から見直す見方、実務で次に効く 1 点、よくある誤解の正体、のどれかを書く。
- 答えの写しにしない：how の問いにそのまま答える文（「4 つの式の結果は…」）を書かない。goal の言い換えにしない：「〜が書けている」を言い直さない。
- 本文を読み返さなくても 1 つの文として立つようにする（S4、S5 では題名と解説だけが並び、why と how は出ない：design 5 の S4、S5）。
- 2 文以内、50〜90 字を目安にする（1 件の予算 480 字に対して本文の平均が 287 字なので、insight は平均 70 字前後に収めた）。
- 出典のない数字や強い断定（「多くのチームで半減」「必ず止まる」）を書かない。
- です・ます。感嘆符、絵文字、命令形を使わない（design 7 の文体に合わせる）。「正解」「答え」の語を使わない（D-38 の見出しの決まりに合わせた）。
