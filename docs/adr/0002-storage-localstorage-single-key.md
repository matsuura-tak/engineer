# ADR 0002：保存は localStorage のキー 1 つ。形は版番号つきで書き出しと同じにし、ID は変えない

- 状態：提案（G1 で reviewer が判定する）
- 書いた役：tech-lead　日付：2026-10-30
- 関係する PRD、設計メモ、契約：docs/prd/001-daily-learning.md（10 のはまりやすい所、11、12）、docs/adr/features/001-daily-learning.md、contracts/data.md、contracts/schemas/data.schema.json、contracts/identifiers.md の 5
- 元に戻す手間：大（利用者のブラウザにある保存データと、書き出したファイルを読み続ける必要がある）

## 背景
- サーバーがないので、正しいデータの置き場所は利用者のブラウザだけ。消えたときの手当ては書き出しと読み込みだけ（AC-19、AC-20、AC-25）。
- PRD は「保存の形式に版番号を付け、書き出しファイルと同じ形にする。今の版以下は移して読み、新しい版は拒む」と決めている（10）。
- AC-11 は「次の 1 回の書き込みだけ失敗させる」注入でテストする。
- origin（matsuura-tak.github.io）は、同じアカウントの他の Pages と共有する。
- design の U-5〜U-8 と U-11 は tech-lead に任された（G1 r1 の A で確定案を出した）。

## 決定
- localStorage のキー `kyounoitte:data` 1 つに、schemas/data.schema.json の形の JSON を入れる。保存＝書き出し＝seed は同じ形（書き出しは `device` を除く）。1 回の保存は 1 回の setItem。
- `formatVersion`（今は 1）を持ち、スキーマは知らない項目を拒む。読み手が知らない項目か値を書く変更は必ず版を上げ、新しいアプリは古い版を移して読む。
- 領域、段階、経験年数、課題の ID は一度決めたら変えない。課題は消さず、ID を使い回さない（identifiers.md の 5）。

## 一緒に決めたこと（design の未決）
- U-5：S0 の error を採る。条件は data.md の 4（保存先が使えない、JSON.parse の失敗、スキーマ不一致、版が新しい）。部分だけ読むことはしない。
- U-6：答えの上限 `answer.max` は 2,000 字。365 日分でも保存データは 1,000,000 字以下で、ブラウザの上限（約 5 MB と言われるが未確認）に余裕がある。
- U-7：やり直しの診断の回答はメモリだけに持ち、「診断を終える」で 1 回だけ保存する。初回の診断は質問ごとに保存する（AC-11）。
- U-8：ID は design の値のまま（`backend` … `git`、`beginner` / `intermediate` / `advanced`、`lt1` … `gte5`、課題は `<領域>-<段階>-<3 桁>`）。
- U-11：答えの欄の `data-testid` は `task.answer`。
- 「保存データあり」は、診断を終えたか履歴が 1 行以上（data.md の 3）。
- 段階は申告を保存するときに変え（data.md の 5）、`levels` に持つ。書き出しに「領域ごとの現在の段階」が入る（AC-19）。
- 申告の「完了」の値は `done`（verifier G0 r3 の W-8 案の `completed` ではなく、design と PRD AC-32 の `none` に合わせた）。
- `firstOpenDate`（統計の「初めて開いた日」）は、保存データが「なし」の状態で初回の診断の 1 問目を確定する保存で書き、以後変えない。`device` だけの保存（案内を閉じた印、persist の印）では書かない。そのためスキーマでは、`diagnosis` と `levels` が空で `history` が 0 行のときだけ省ける（data.md の 2 と 3。pdm の G1 の確認：iOS の Safari だけ案内を閉じた日が初日になり、first-day-completed が他のブラウザとずれるのを防ぐ）。v1 はまだ配っていないので、版は上げない（前の形で通った見本 18 件は、今の形でも合否が同じ）。

## 検討した案
| 案 | 良い点 | 悪い点 | 選ばなかった理由 |
|---|---|---|---|
| (a) localStorage のキー 1 つ（採用） | 読み書きが同期で、状態の決め方が単純。書き出しが文字列そのまま。AC-11 の注入が setItem 1 つで済む。全体が通るか落ちるかの 2 択 | 1 origin あたり約 5 MB（未確認）。毎回全体を書く。同じ origin の他のページから読める | — |
| (b) IndexedDB | 大きい。非同期で画面を止めない。項目ごとに書ける | 非同期の手順と移し方（onupgradeneeded）が増える。書き出しには組み立てが要る。失敗の注入が難しい | 365 日分でも 1 MB 程度で、(a) の大きさの利点が要らない |
| (c) localStorage の複数のキー（診断、履歴、今日を別々に） | 書く量が減る | 2 つのキーの書き込みの間で失敗すると、ちぐはぐな状態が残る。版をキーごとに持つ必要 | 「1 回の保存＝1 回の setItem」が崩れ、AC-11 と壊れたデータの扱いが難しくなる |
| (d) 知らない項目を無視する緩いスキーマ（版を上げずに足す） | 足すだけなら古いアプリも読める | 古いアプリが書き出すと、知らない項目が黙って消える | データが黙って消えるより、「読めない」と言って止まる方が直せる |

## いちばん強い反論と、それでも選んだ理由
- 反論：localStorage は Safari の 7 日の消去の対象で、同じ origin の他のページから読み書きでき、上限も確かめていない。IndexedDB の方が「ちゃんとした」置き場所ではないか。
- それでも選んだ理由：7 日の消去は IndexedDB も同じ対象で、手当ては書き出しと読み込みしかない（PRD 7 の行 2）。origin の共有は置き場所を変えても同じ（ADR 0005）。大きさは 365 日分で上限の 1/5 以下と見込める。単純さを優先し、上限に近づいたら (b) に移す。

## 結果
- 楽になること：保存、書き出し、seed、見本が 1 つのスキーマで検査できる。テストの注入が単純。
- 難しくなること、守り続けること：
  - 版を上げるたびに、1 版ずつ移す手順と、contracts/fixtures/data/v<n>/ の見本を足し、古い見本を読み続ける単体テストを残す。
  - 課題の ID と語彙を変えない。課題集を直すときは中身を直し、ID は変えない。
  - 保存データが「なし」か「診断の途中」の起動では setItem を呼ばない（AC-11 の注入はこの状態で行う）。「あり」の起動では data.md の 2 のとおり最大 1 回（日付が変わった課題を `none` の行に移す、今日の課題を出す。AC-6、AC-32）。他のキーに触らない。
- 元に戻すとき（(b) に移す）：新しい版のアプリが localStorage を読んで IndexedDB に移し、キーを消す。書き出しの形は変えない。3〜5 日と、移す手順のテスト。

## 見直す条件
- 保存データの文字列が 1,000,000 字（ブラウザの上限の推定の約 1/5）を超える利用者が出た、または QuotaExceededError の報告が 1 件でも来た。
- 「データが消えた」の報告が 30% 以上（PRD 14 の撤退基準）。
- 端末の間で自動で同期したい、またはサーバーを持つと決めた（002 以降）。

## 確かめたこと
- `node contracts/tools/check-schemas.mjs`（ajv 8.20.0、Ajv2020 の strict）：data.schema.json はメタスキーマに通り、data の見本 22 件（valid 5、seed 3、invalid 14）がすべて期待どおり（2026-10-30、firstOpenDate の見本 4 件を足した後。足す前は 18 件）。出力は設計メモの 4。
- `firstOpenDate` の条件（2026-10-30、スクラッチパッドの ajv 8.20.0）：`device` だけ → true、`device` だけ＋persist の印 → true、`device` だけ＋1 問目で `firstOpenDate` なし → false（`/diagnosis must NOT have more than 0 properties`）、同じく `firstOpenDate` あり → true。072d0e3 の形で通った・落ちた data と seed の見本 18 件は、今の形でも合否が 18 件とも同じ（緩めただけ）。
- tech-lead G0 r1 の spike 4（setItem の失敗の注入）と G1 r1 の spike 2（版を差し替えても履歴 3 件が残った）。
- localStorage の上限の数字：未確認（ブラウザの公式な数字を見つけていない。実機の G4 でも測らない。見直す条件で監視する）。
