## 1. 問いと範囲
- この調査で決めたいこと：
  1. 画面の流れ：初回（診断3問 → 今日の課題）と2回目以降（開いたら課題）を、何画面で、どんな並びにするか
  2. 1日1つの見せ方：課題の4要素（題名、なぜ今これか、やり方、完了の目安）と4つの申告を、1画面にどう置くか。「今日は終わり」をどう見せるか
  3. 答えを書く欄：任意で、1秒以内に保存し、同じ日に復元する欄（AC-32）をどう見せるか。保存されたことをどう伝えるか
  4. 外で行う課題の印：`external` の印と要る道具（AC-30）を、色だけに頼らずどう見せるか
  5. 空の状態と知らせ：課題が尽きた（AC-10）、履歴が0件、ホーム画面の案内（AC-21、AC-22）、保存の永続化を断られた（AC-13）、読み込みの失敗（AC-25）、保存の失敗（AC-11）
  6. 統計の見せ方：13 の指標と1対1の 9 つの値（AC-24）を、利用者がスクリーンショットで送れる1画面にどう並べるか
  7. 日英の文言：調子（5）と、英語で長くなっても崩れない並び（AC-26）
  8. ダークモードと文字サイズ：OS の設定に従う形（独自の切り替えを持つか）、本文の最小サイズ、320 CSS px での並び（AC-17）、フォーカスの枠（AC-18）、コントラスト（AC-27）
  9. ブランドの性格語と、競合に対する「差をつける点」
  - r2 の追記（PRD r10。FB-1〜FB-3）：
  10. 完了した直後の画面（`task.rate` と `task.done`）：祝いの動き、言葉、累計の見せ方、節目（7、30、100 件）を、連続記録を持たない形で、前庭障害（動きを減らす設定）と罪悪感への配慮を保ってどう出すか（AC-35）

  13. 未経験の人向けの入口：領域の 1 行説明（AC-39）、経験年数「まだコードを書いたことがない」（AC-40）、段階の説明、専門用語の扱い、最初の 1 件の不安を減らす見せ方
  14. ひとこと解説（`insight`）を完了の後にだけ出す見せ方。答えの写しに見えない形（AC-38）
  15. 今週の完了日（月曜始まり）の見せ方。途切れや「逃した」を感じさせない形（AC-37）

  16. 選択式の問題の画面：問題文、選択肢 3 つ、正誤の返し、選んだ答えに合わせた説明、「次の問題へ」をどう並べるか。タップの的、選んだ瞬間（300 ミリ秒以内）の動き、正解と不正解の色と形（色だけに頼らない）、選び直しをさせない見せ方（AC-41、AC-42、AC-17）

## 2. ターゲット（仮説）
人に聞いた調査ではなく、PRD とレビューなどから立てた仮説として書く（PRD の Q8 は回答なしのため、すべて［推測］に当たる）。
- 誰が（仮説）：日本のソフトウェアエンジニアで実務1〜5年目（docs/prd/product.md の対象の層。［推測］と明記されている）。すでにコードを書いていて、「次に何を学ぶか」を決める時間が惜しい人。英語の UI を避けたい人が JP の学習アプリのレビューに一定数いる（PRD の E-5：Sololearn 57件中 7件、Mimo 47件中 7件が「日本語に対応してほしい」）。
- 使う場面（仮説）：平日の朝か通勤中、スマホのブラウザで片手、15分（PRD 2 の Job ストーリー）。開いてから課題が見えるまで2秒・操作0回（AC-15、AC-31）。PC のブラウザは副（product.md）。iOS では「ホーム画面に追加」から開く人もいる（AC-21、AC-22。R-24）。
- 起こしたい感情：「今日も前に進んだ」（PRD 2 の気持ちの面）。開いた瞬間は「迷わない」、終えた瞬間は「今日はここまででいい」。手本の Wordle は1日1つの制約で「1日3分だけ使う」ことを意図した（R-6）。
- 見た目の好み（色の量、情報の密度）と根拠：色は少なく、密度は低く、1画面1件にする。根拠：(1) 教育水準が高いほど「カラフルさ」の好みが下がる（R-13。対象はエンジニアで、高等教育を受けた人が多いと仮定［推測］）。(2) 「パーソナル」を掲げる Enki のレビューに「just how busy the screen is」「The progress bar on top when you scroll down is a little distracting」（R-2）があり、競合の密度そのものが不満になっている。(3) roadmap.sh は「All 96 roadmaps」の高密度な一覧で、PRD の E-1 の「learn everything at once will slow you down」の不満につながる（R-5）。(4) 手本の Wordle は、色を黄・緑の2つの意味にだけ使い、ルールは10行未満の案内で足りる（R-7）。
- アクセシビリティで必要なこと：
  - 文字の拡大：幅 320 CSS px（200% 相当）で横スクロール 0（AC-17。R-16）。本文は 16 CSS px 以上、14 px 未満は使わない（R-26）。入力欄は 16 px 以上にしないと iOS Safari がフォーカスで拡大する（R-25）。
  - キーボード：Tab と Enter と Space だけで診断から完了まで（AC-18）。選択肢はラジオグループの型（R-21）。フォーカスの枠は 2 CSS px 以上（AC-18）で、周囲と 3:1 以上（R-15）。
  - コントラスト：本文 4.5:1、大きい文字（24 px 以上、または 18.5 px 以上の太字）と操作部品の枠は 3:1（R-14、R-15）。
  - 押せる範囲：WCAG AA は 24×24 CSS px（R-17）だが、片手のスマホ操作を主と置くので、主操作と申告のボタンは AAA の 44×44 CSS px を目標にする（R-17）。
  - ダークモード：OS の設定に従う（R-22）。動きを減らす設定では切り替えのアニメーションを消すか不透明度の変化だけにする（R-23）。
  - 色だけで意味を伝えない：外で行う印、保存済みの印、申告の結果は、文字とアイコンを併記する（R-7 の High Contrast Mode の例。R-15 の「状態」の条項）。
  - 読み上げ：答えの欄の「保存しました」のような状態の知らせは、フォーカスを奪わずに `role="status"` で伝える（R-19）。

### 2.1 r2 の追記（FB-1〜FB-3 で広がった対象。仮説）
- 誰が（仮説を広げた）：主の対象に「コードをほとんど書いたことがない人」（段階「初級」）を足す（docs/prd/product.md r5、PRD r10 の 2）。Progate の対象と重なる層で、「当たり前のように専門用語を使ってきて腹が立ちました」（PRD の E-12、2020-03-19）が入口の不満。未経験の読者は手元にいない（PRD 6 の実現性の行）ので、文言は NN/g の「技術用語は先に説明する」（R-55）と GOV.UK のヒント文の型（R-54）で代える。
- 使う場面（足した）：「休日にまとめて進めたい日」（PRD 2 の Job ストーリー。FB-2）。通勤の 15 分だけでなく、腰を据えて 3 件以上続ける日がある。続ける操作は、1 件ごとに完了画面を経て「次の一手に進む」を押す（AC-33）ので、完了画面が 1 日に何度も出る。何度も出る画面は、動きで待たせない（R-32「Let people cancel motion」、R-41「down-time animations ... frustrate」）。
- 起こしたい感情（足した）：終えた直後に「小さな発見があった」（`insight`。PRD 2 の気持ちの面）と「前に進んだ数が増えた」（累計、n / N）。途切れや失う恐れは起こさない（PRD の E-15、E-16。R-46 の「a missing day reads like an error you want to fix」の逆）。FB-3 の「ワクワク」は、ここでは「次に出る解説と次の段階を見たくなる」こと（白帽の達成と有能感。PRD の E-16、E-17）と読み、演出の派手さではなく「返ってくるもの」で作る（5 の r2 の性格語「手応え」）。
- 見た目の好み（変えない）：色は少なく、密度は低く。未経験が入っても、R-13（教育水準が高いほどカラフルさの好みが下がる）の仮定は対象の主（エンジニア志望か在職）に残る。Progate の「にんじゃわんこ」「ひつじ仙人」（R-50）のようなキャラクターは PRD の S-9 で v1 では捨てた。
- アクセシビリティで必要なこと（足した）：祝いの動きは `prefers-reduced-motion: reduce` で消す（R-33、R-38、R-40）。自動で動く要素は 5 秒を超えない（R-39）。累計の数字を大きく出すときも、文字だけで意味が分かるラベルを付ける（R-34「Make sure all feedback is accessible」）。

### 2.2 r3 の追記（FB2 で分かった「退屈」と「分かりにくい」。仮説）
- 誰が（変えない）：主は実務 1〜5 年目のエンジニアと、コードをほとんど書いたことがない人（2.1）。FB2 を書いた Takuma 自身がこの対象の代理であり、r2 の文字だけの課題を「文字だけだと退屈するし理解がむずかしい」「書き方ややり方がイマイチ」と評した（docs/approvals/001-daily-learning-FB2.md）。r1 と r2 の「色は少なく、密度は低く」（R-13）は、「飾りを置かない」の意味では残し、「図と絵を置かない」の意味では取り下げる。
- 使う場面（足した）：1 問ごとに「選ぶ → 返しを読む → 次へ」を 1 日に 3 回（続ける日は 9 回以上）繰り返す。繰り返す操作なので、返しの動きは短く（R-67「generally avoid adding motion to UI interactions that occur frequently」）、説明は選択肢の直近に出す（R-66「near the items it describes」、R-74 の spatial contiguity）。
- 起こしたい感情（足した）：選んだ直後に「合っていた」か「なぜ違うか」が分かり（R-75 の「正解と自分の答えを並べる」型。E-27 の「どうして間違えたかを…解説してくれるから…どんどん進んで」）、不正解でも「責められない」（E-27 の「間違えたら、リリーが笑ってくる」の逆）。図は「読む前に形が分かる」安心（R-74 の multimedia、signaling）。キャラクターは「隣にいる」感じで、「見張られている」感じにしない（R-77 の「you are disappointing Duo」は採らない型）。
- 見た目の好み（変えた）：色は「意味色＋図の強調 1 色＋キャラクターの固有色」までを上限の候補にし（7.2 の 2 案）、密度は 1 問が幅 320 で 1 画面に収まる程度（PRD 10「選択肢を 4 つにしたくなる」の理由と同じ）。R-13 の「教育水準が高いほどカラフルさの好みが下がる」は残るので、色を増やすなら「意味を持つ色」だけにする（R-68「reserve it for elements that truly benefit from emphasis」）。
- アクセシビリティで必要なこと（足した）：正誤は文言と印と色の 3 つで出す（R-69、R-70）。赤と緑の対で正誤を分けない（R-69「pairings such as red-green」）。図の線と枠は 3:1 以上（R-71）、文字は 4.5:1（R-69）。キャラクターの絵は `aria-hidden`、台詞は文字で読め、動きは `prefers-reduced-motion: reduce` で 0 件（R-72。AC-45）。拡大は整数倍でぼやけさせない（tech-lead r5 の 3）。

## 5. ブランドの性格語と文言の調子
性格語は4語。NN/g は「a set of 3–7 words that express the essence of your Brand」を選び、語ごとに意味を定めて文言、書体に当てることを勧める（R-12）。

| 性格語 | 意味すること | 意味しないこと |
|---|---|---|
| ひとつ | 1画面に1件、主操作は1つ。今日の課題だけが画面の中心にあり、一覧や地図を見せない（R-5 の対極、R-6） | 機能が少ないこと。設定、履歴、統計は「ひとつ」の外に置くだけで、消さない（AC-16、AC-19、AC-24） |
| 静か | 色は意味色だけ、動きは最小、飾りと絵文字を置かない（R-2 の「busy」の不満、R-13）。通知もハートも急かさない（PRD 10） | 冷たい、素っ気ない。完了の瞬間には一言の労い（「今日も前に進みました」のような、確かめられる事実の言い方）を置く |

- ていねい ⇔ ちゃかす：「ていねい」。申告の文言は本人を責めない（「今日はできない」は選択肢として並べ、理由を聞かない）。

- r3 の追記（FB2-4、FB2-5。性格語を 5 語から 6 語にする。NN/g の 3〜7 語の範囲。R-12）：

| 性格語 | 意味すること | 意味しないこと |
|---|---|---|
| 一緒に（r3 で足した） | 案内役は評価者ではなく同席者。正解でも不正解でも同じ大きさで隣にいて、不正解では「一緒に考える」顔になる（PRD 9、AC-45。R-85 の「drawn simply」、E-27 の「笑ってくる」の逆）。図は読む人の理解を助ける 1 枚（R-74 の multimedia） | なれなれしい。台詞で会話を長引かせる。ペットのように世話をさせる（PRD 10）。「you are disappointing Duo」（R-77）のような情緒的な負債 |

## 6. 合わせる当たり前と、差をつける点
- 合わせる当たり前（利用者がほかのアプリで覚えた型）と R 番号：
  - 1画面1問の診断と「n / 3」の進み具合（R-8。GOV.UK の「one thing per page」：モバイルで使いやすく、回答を自動で保存できる。AC-1 の「n / 3」と AC-11 の保存の失敗に合う）。
  - 選択肢はネイティブのラジオボタンの型（Tab でグループに入り、矢印で移動、Space で選ぶ。R-21）。
  - 取り消せない操作（全削除、読み込みの置き換え）は確認のダイアログ（`role="dialog"`、`aria-modal="true"`、Escape で閉じる、閉じたら呼び出し元へフォーカスを戻す。R-20）。
  - 空の状態は「何が起きたか」と「次の一手のボタン」（R-9。「Tell the user what could be displayed, and how to populate the area with that content」）。読み込み中に「0件」を出さない（R-9）。
  - エラーは問題の近くに、何が起きたかとどう直すかを書き、入力を保つ（R-10。AC-11）。
  - ダークモードは OS の設定に従い、`<meta name="color-scheme" content="light dark">` と `prefers-color-scheme` で切り替える（R-22）。独自の切り替えボタンは置かない（設定が増えるため。B-2）。
  - 動きを減らす設定に従う（R-23）。
  - iOS の「ホーム画面に追加」の作法：`apple-touch-icon`（180×180）、`apple-mobile-web-app-capable`、起動画像、`navigator.standalone` での判定（R-24。PRD の 11 の冒頭と同じ）。
  - 本文 16 CSS px 以上、行間 1.5 以上（1.6〜1.7 を目安）、14 px 未満を使わない（R-26）。入力欄も 16 px 以上（R-25）。
  - 固定ヘッダーやバナーでフォーカスを隠さない（R-18）。案内（AC-21、AC-22）は課題を覆わない（AC-31 の「重なる要素 0 件」と同じ）。
- 差をつける点（1から2個。どの画面のどの瞬間か）と R 番号：
  1. **課題そのものがホーム画面**。開いた瞬間（`task.today` の初期表示）に、一覧も地図もダッシュボードも挟まず、今日の課題の題名が最初の見出しとして出る。競合は登録（R-2、R-3、R-4）か地図の一覧（R-5）が先で、「今日の1件」までが遠い。手本の Wordle は開いたら盤面（R-7）。決定的な瞬間は「読み込みが終わった0.5秒後に、題名と『なぜ今これか』が読める」こと（AC-31、AC-15）。
  2. **「今日はここまで」と言い切る終わりの画面**。`task.done` と `task.skipped` は、次の課題もストリークも見せず、「今日の一手は終わりです。次は明日」と1文で終える（R-6 の「spend only three minutes」の意図、PRD 10 のストリーク非採用）。完了の直後の `task.rate` は1問だけで、答えなくても閉じられる（AC-9）。決定的な瞬間は「完了を押したあと、画面が静かになる」こと。
  - どちらも、デザインの採点と判断（見た目の良さではなく「迷わない」「終われる」）に結び付く。仕様では `task.today` と `task.done` の2画面に表れる。

  - 終えた直後に「返すもの」（指標、解説、進み具合）を 1 画面で見せる（R-44 の Duolingo の完了画面、R-53 の確認ページ）。ただし画面を分けて「Continue」を重ねない。
  - 節目は少ない日だけ特別にする（R-42、R-43）。
  - 進み具合は「n / N」の文字で出す（GOV.UK のタスクリストは「Completed」を文字で示す。R-65。HIG の progress indicator は待ち時間用の一時的な部品なので、学習の進み具合には使わない。R-37）。
  - 選択肢の補足はヒント文（1 文、句点なし、リンクなし。R-54）。
  - 動きは短く、取り消せて、`prefers-reduced-motion` で消える（R-32、R-33、R-38、R-40）。
- 差をつける点（r1 の 2 を置き換える）：
  2. **終えた直後に、静かに返ってくる「手応え」**。`task.rate`（と `task.done`）は、紙吹雪も「Continue」の連鎖もなく、1 画面に「ひとこと解説」と累計（n 件目）と「役に立ったか」の問いだけを置く。競合は完了を 4 画面以上の演出と報酬に分け（R-44）、連続記録の数字で次の日を縛る（R-46、R-47）。当アプリの決定的な瞬間は「『完了』を押した 0.5 秒後に、その課題でいちばん大事な 1 文が読め、累計が 1 増えている」こと（AC-35、AC-38）。「次の一手に進む」は同じ画面の末尾に副操作として 1 つだけ置き、押さなければ「明日も 1 件出る」で終われる（AC-33、PRD の P-2）。
  - r1 の「今日はここまでと言い切る」は、FB-2（同じ日に続ける）で成り立たなくなったので取り下げる。「終われる」こと自体は残す：主操作にしない、確認や催促を出さない（R-60）、再読み込みしても同じ画面（R-53）。
  - 差をつける点 1（課題そのものがホーム画面）は変えない。n / N と「次の一手」が入っても、開いた直後の `task.today` に重なる要素は 0 件のまま（AC-31）。

### 6.2 r3 の追記（FB2 で変わった点）
- 合わせる当たり前（足した）：
  - 選択肢は縦に並べ、答えると正誤と説明がその場に出て、「次へ」で進む（R-75 の Duolingo、R-82 の Pythonプログラミング入門。E-26「間違えた時の解説が充実」）。
  - 正誤は文言と記号と色の 3 つで示す（R-66、R-69、R-70）。
  - 返しの動きは短く、`prefers-reduced-motion` で消える（R-67、R-72）。
  - 案内役は正解のときに表情を変える（R-76）。
  - 図はラベルを短く、幅を使い切り、色だけに頼らない（R-73）。
- 差をつける点（r2 の 2 を置き換える。r1 の 1 は変えない）：
  2. **選んだ直後の 0.3 秒に、「なぜ」が必ず出て、案内役が不正解でも同じ顔の大きさで隣にいる**。競合は説明を任意で開かせ（R-75）、正解のときだけキャラクターが動き（R-76）、不正解で笑う（E-27）か、説明が「曖昧かつ断片的」（E-26）になる。当アプリは、選んだ選択肢の説明と正解の説明を必ず並べ（AC-41）、案内役は正解と不正解で表情だけを変え、台詞は事実か問いだけ（AC-45）。r2 の「終えた直後の手応え」（解説、累計、n / N）はこの 2 の続きとして `task.rate` に残す。
  - 図（6 型）は「差をつける点」ではなく「合わせる当たり前」側に置く。Progate と Brilliant が図を中心に据えている（R-81、R-83）ので、図があること自体は差にならない。差になるのは「課題集が型とラベルだけを持ち、アプリが描く」作りで、これは見た目ではなく実装の差（AC-44）。

### 7.2 r3 の方向性：pop の度合い（FB2-4。色数 3 と 5。最終の選択は Takuma。PRD 9 の図の行、AC-44）
今のトークン（design/tokens.md r7）は、地と文字の 2 色に、主操作の青（color.action.primary）と意味色 3 つ（success、warning、error）を持つ。「色数」はここでは「意味色を除いた、見た目のためのアクセント色の数」で数える。
